# vfs-core

Общие типы и интерфейс файловой системы, а также VFS с маршрутизацией по
префиксам и таблицей открытых файлов. Всё находится в одном крейте.

## Интерфейс файловой системы

`FileSystem` описывает операции над узлами одного экземпляра ФС:

| Метод | Назначение |
| --- | --- |
| `root()` | ID корневого каталога |
| `lookup(parent, name)` | Найти непосредственного потомка по имени |
| `metadata(node)` | Получить тип, размер и атрибуты узла |
| `set_metadata(node, update)` | Изменить выбранные атрибуты узла |
| `read_dir(directory)` | Получить записи каталога в порядке имён |
| `create(parent, name, kind)` | Создать файл или каталог |
| `read(file, offset, buffer)` | Прочитать данные с заданного смещения |
| `write(file, offset, data)` | Записать данные |
| `truncate(file, length)` | Изменить размер файла |
| `remove(parent, name)` | Удалить файл или пустой каталог |

`NodeId` имеет смысл только внутри своей ФС. `Metadata` содержит `kind`, `size` и атрибуты CPIO newc: `mode`,
`uid`, `gid`, `nlink`, `mtime`.
Размер каталога равен нулю. `Metadata::new(kind)` задаёт атрибуты пустого узла
с правами 0644/0755, владельцем 0, числом ссылок 1 и нулевыми остальными полями.
`DirEntry` содержит имя, локальный ID и тип узла.

VFS сама обходит внутренний путь через последовательные вызовы `lookup`.

## API VFS

| Метод | Назначение |
| --- | --- |
| `Vfs::new()` / `Vfs::default()` | Создать пустую VFS |
| `register(prefix, Box<dyn FileSystem>)` | Передать ФС во владение VFS, получить `FsId` |
| `unregister(fs_id)` | Отключить и освободить конкретную ФС |
| `registered_prefixes()` | Перечислить пары `(FsId, &str)` в порядке регистрации |
| `read_dir(path)` | Перечислить записи каталога выбранной ФС |
| `metadata(path)` | Получить метаданные по абсолютному пути |
| `set_metadata(path, update)` | Изменить выбранные атрибуты по абсолютному пути |
| `open(path)` | Открыть обычный файл, получить `FileDescriptor` |
| `read(fd, buffer)` | Прочитать с текущей позиции открытия |
| `close(fd)` | Удалить открытие |

Через VFS содержимое файлов доступно для чтения. Изменение метаданных
зависит от реализации ФС. По умолчанию изменяющие методы `FileSystem`
возвращают `FsError::Unsupported`.

В `MetadataUpdate` передаются только поля, которые нужно изменить.
`Some(value)` задаёт новое значение, а `None` сохраняет текущее.
Поле `permissions` принимает права и специальные биты Unix (до `0o7777`).
Тип узла и размер определяются самой ФС, а `nlink` хранится как атрибут архива.

## Пути и подключения

Пути и префиксы должны быть абсолютными. Пустая строка, относительный путь,
NUL и любой компонент `..` дают `VfsError::InvalidPath`.
Повторные `/` объединяются, компоненты `.` пропускаются:

```text
//data/./file → /data/file
/data/../file → InvalidPath
```

Нормализация выполняется до выбора ФС. Имена вроде `..file` разрешены:
запрещён только отдельный компонент `..`.
Конечные `/` и `.` требуют каталог; открытие каталога как файла запрещено.

На безопасность имена никак не провряется.

Выбирается самый длинный префикс с учётом границ компонентов:

- `/data` подходит для `/data/file`, но не для `/database/file`.
- При подключениях `/` и `/data` путь `/data/file` обслуживает `/data`.
- Если файл не найден в выбранной ФС, поиск в родительской ФС не продолжается.
- Точное совпадение пути и префикса обозначает корень выбранной ФС.

Подключение `/` необязательно. Оно подходит ко всем абсолютным путям,
если нет более длинного подходящего префикса. Чтобы найти доступные точки
входа без подключения `/`, используйте `registered_prefixes()`.
`read_dir(path)` возвращает реальные записи каталога выбранной ФС.
Зарегистрированные префиксы сами по себе не добавляют записей в каталоги.

Корень переданной ФС должен быть каталогом.

## Открытые файлы

Каждое открытие хранит `(FsId, NodeId, offset)`. `read` вызывает реализацию ФС 
один раз и сдвигает позицию на возвращённое число байтов.
Для обычного файла `0` с непустым буфером означает EOF;
пустой буфер тоже даёт `0`, но по нему нельзя судить об EOF.
При ошибке позиция не меняется; неизменность буфера после ошибки не гарантируется.

Закрытый дескриптор недействителен даже при чтении в пустой буфер.
Пока есть открытия этой ФС, `unregister` возвращает `Busy`.

`FsId` и `FileDescriptor` — непрозрачные типы на основе `u64`. Они выдаются
без повторного использования в пределах одноой `Vfs`; исчерпание счётчика
возвращает `IdentifierExhausted`.

## Пример с MemFs

```rust
use memfs::MemFs;
use vfs_core::{FileSystem, NodeKind, Vfs};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut fs = MemFs::new();
    let file = fs.create(fs.root(), "hello.txt", NodeKind::File)?;
    fs.write(file, 0, b"hello")?;

    let mut vfs = Vfs::new();
    let fs_id = vfs.register("/data", Box::new(fs))?;
    let fd = vfs.open("/data/hello.txt")?;
    let mut contents = Vec::new();
    let mut buffer = [0; 2];
    loop {
        let count = vfs.read(fd, &mut buffer)?;
        if count == 0 {
            break;
        }
        contents.extend_from_slice(&buffer[..count]);
    }
    assert_eq!(contents, b"hello");
    vfs.close(fd)?;
    vfs.unregister(fs_id)?;
    Ok(())
}
```
