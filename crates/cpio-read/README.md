# cpio-read

Самостоятельный парсер несжатого CPIO `newc`

`read_archive` принимает `&[u8]` и возвращает `Result<Vec<Entry<'_>>, Error>`.
Имена (`&str`) заимствуются из исходного архива. `data_range` хранит диапазон
содержимого относительно начала архива. Получить срез можно через
`&bytes[entry.data_range.clone()]`.

Из корня репозитория:

```sh
cargo run -p cpio-read --example read_archive -- crates/cpio-read/tests/fixtures/sample.cpio
cargo test -p cpio-read
cargo build -p cpio-read --lib --target x86_64-unknown-none
```

Тест сравнивает байты файлов с исходниками, включая пустой и бинарный файлы,
и проверяет тип каталога. Повреждённые записи, отсутствие trailer и ненулевой хвост
проверяются отдельными тестами. Ошибка содержит категорию `kind` и смещение
`offset` от начала архива. Для ошибки записи это начало её заголовка,
для отсутствующего trailer — конец входных данных, для ненулевого хвоста —
позиция первого ненулевого байта.

Поддерживается только `newc` (magic `070701`). Требуется `TRAILER!!!` с нулевым размером данных;
после него допустимы только нулевые байты. Имена должны быть валидным UTF-8.

`Entry` сохраняет атрибуты заголовка newc: `ino`, `mode`, `uid`, `gid`,
`nlink`, `mtime`, `devmajor`, `devminor`, `rdevmajor`, `rdevminor`.
Все имеют тип `u32`; `mtime` — секунды с начала эпохи Unix, `mode` включает
тип файла и права. Размер содержимого доступен как `entry.data_range.len()`.
