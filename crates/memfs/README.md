# memfs

Файловая система в оперативной памяти, реализующая `FileSystem` из `vfs-core`.
Поддерживает только  обычные файлы и каталоги.

## Структура и хранение

`MemFs::default()` создают пустую ФС с корневым каталогом
`NodeId::new(0)`. Узлы хранятся в `BTreeMap<NodeId, Node>`:
файл содержит `Vec<u8>`, каталог — `BTreeMap<String, NodeId>` своих детей.

`NodeId` локален для экземпляра MemFs. Новые ID выдаются последовательно
и не используются повторно после удаления. При исчерпании `u64` создание
возвращает `FsError::IdentifierExhausted`.

## Пример использования

```rust
use memfs::MemFs;
use vfs_core::{FileSystem, NodeKind};

fn main() -> vfs_core::Result<()> {
    let mut fs = MemFs::new();
    let root = fs.root();
    let docs = fs.create(root, "docs", NodeKind::Directory)?;
    let file = fs.create(docs, "hello.txt", NodeKind::File)?;
    fs.write(file, 0, b"hello")?;

    assert_eq!(fs.lookup(docs, "hello.txt")?, file);
    assert_eq!(fs.metadata(file)?.size, 5);
    assert_eq!(fs.read_dir(docs)?[0].name, "hello.txt");

    let mut buffer = [0; 3];
    let first = fs.read(file, 0, &mut buffer)?;
    assert_eq!(&buffer[..first], b"hel");
    let second = fs.read(file, first, &mut buffer)?;
    assert_eq!(&buffer[..second], b"lo");

    fs.remove(docs, "hello.txt")?;
    fs.remove(root, "docs")?;
    Ok(())
}
```

## Операции

| Метод | Поведение |
| --- | --- |
| `root()` | ID корневого каталога |
| `lookup(parent, name)` | Найти ребёнка каталога по имени |
| `metadata(node)` | Тип и размер в байтах; для каталогов размер 0 |
| `read_dir(directory)` | Непосредственные дети в порядке имён, без `.` и `..` |
| `create(parent, name, kind)` | Создать пустой файл или каталог |
| `read(file, offset, buffer)` | Скопировать доступные байты начиная с offset |
| `write(file, offset, data)` | Записать байты, при необходимости расширить файл |
| `truncate(file, length)` | Укоротить или расширить файл |
| `remove(parent, name)` | Удалить файл или пустой каталог |

Пустое имя, `.`, `..` и имя с `/` отвергаются с `InvalidName`.
Родитель должен существовать и быть каталогом; имя должно быть свободным.

### Чтение и изменение размера

`read` возвращает число скопированных байтов, не превышающее размер буфера.
На EOF, за EOF и при пустом буфере возвращается `0` для существующего файла.
Хвост буфера после скопированных байтов остаётся неизменным.

`write` перезаписывает диапазон; при записи за концом файла промежуток
заполняется нулями. Пустая запись не расширяет файл даже при большом смещении.
`truncate` удаляет хвост при уменьшении и добавляет нули при увеличении.

### Удаление

Непустой каталог удалить нельзя (`DirectoryNotEmpty`). После удаления узел
больше не существует, его старый `NodeId` даёт `NotFound` и не переиспользуется.

## Подключение к VFS

```rust
use memfs::MemFs;
use vfs_core::{FileSystem, NodeKind, Vfs};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut fs = MemFs::new();
    let file = fs.create(fs.root(), "config.txt", NodeKind::File)?;
    fs.write(file, 0, b"mode=demo\n")?;

    let mut vfs = Vfs::new();
    let id = vfs.register("/data", Box::new(fs))?;

    assert_eq!(vfs.metadata("/data/config.txt")?.size, 10);

    let fd = vfs.open("/data/config.txt")?;
    let mut buffer = [0; 32];
    let count = vfs.read(fd, &mut buffer)?;
    assert_eq!(&buffer[..count], b"mode=demo\n");

    vfs.close(fd)?;
    vfs.unregister(id)?;
    Ok(())
}
```

## Ошибки и ограничения

Операции возвращают `vfs_core::Result<T>` с `FsError`:
`NotFound`, `AlreadyExists`, `InvalidName`, `NotDirectory`, `IsDirectory`,
`DirectoryNotEmpty`, `SizeOverflow`, `IdentifierExhausted`.

## Проблемные имена и недоверенные данные

- **NUL.** Прямой `create` сейчас допускает NUL внутри имени. VFS запрещает его
  во внешнем пути, поэтому созданный напрямую узел с таким именем недоступен
  через путь VFS. Это известное расхождение проверок двух уровней.
- **Управляющие символы.** Перевод строки, табуляция и ESC разрешены в имени.
  При выводе без экранирования они могут нарушить формат журнала или управлять
  терминалом. Для диагностики выводите имя через `{:?}`; при экспорте в другой
  формат используйте экранирование именно для этого формата.
- **Неоднозначное отображение Unicode.** Похожие буквы разных алфавитов,
  комбинируемые символы и символы направления текста могут создавать обманчивые
  имена. Сравнение имён точное и чувствительное к регистру; нормализации нет.
- **Исчерпание памяти.** Лимитов длины имени, числа узлов и общего объёма данных
  нет. Большие записи, `truncate` и запись далеко за EOF выделяют память, включая
  нулевой промежуток. Например, запись одного байта с большим смещением может
  потребовать большой буфер. `SizeOverflow` проверяет представимость размера,
  но не доступность памяти и не заменяет квоту.
- **Ошибки использования NodeId.** ID принадлежит конкретному экземпляру MemFs.
  ID из другой ФС может случайно совпасть с существующим местным узлом и обратиться
  к нему: сам тип не хранит принадлежность экземпляру. После удаления ID становится
  недействительным и не используется повторно в этом экземпляре.

Точное имя `..` и имена с `/` запрещены прямыми операциями MemFs; строки вроде
`..file` допустимы и не означают переход к родителю. MemFs не интерпретирует
имена как команды и не обращается по ним к файловой системе хоста.

При работе с недоверенным источником вызывающему коду следует ограничивать
размеры и количество объектов, проверять имена по требованиям приложения
и безопасно отображать их. Перечисленные ограничения здесь документированы;
дополнительные проверки и квоты в этой реализации не добавлены.
